# ADR-016 — Fix Price Coverage Gaps and Holdings Data Integrity

## Status
Accepted

## Date
2026-04-25

## Context

After Phase 2a verification, 10 non-manual assets have null `current_price` in the holding
table. Investigation (session 6) identified three distinct root causes. Additionally a data
integrity check revealed one asset with confirmed investment transactions has no holding record.

---

## Issues Found

### Issue 1 — ACME (Acme Corp): Missing Holding Record

**Root cause:** The seed migration created `investment_transaction` rows for asset_id=60 (ACME)
but never inserted a corresponding row in the `holding` table. The `POST /portfolio/holdings/refresh`
endpoint runs `UPDATE holding SET current_price = $1 WHERE asset_id = $2` — when no holding
row exists, this silently touches 0 rows and still increments the `updated` counter. The price
API (Finnhub, correct for NYSE-listed ACME) is not at fault.

**Integrity query** (run after any data migration to detect regressions):
```sql
SELECT a.id, a.name, a.ticker_symbol
FROM investment_transaction it
JOIN asset a ON a.id = it.asset_id
LEFT JOIN holding h ON h.asset_id = a.id
WHERE it.status = 'confirmed'
  AND h.asset_id IS NULL
GROUP BY a.id, a.name, a.ticker_symbol;
```
Expected result: 0 rows. If any rows are returned, run the fix SQL below.

**Fix SQL** (idempotent — safe to re-run):
```sql
INSERT INTO holding (asset_id, quantity, avg_cost, total_invested, current_price, current_value, updated_at)
SELECT
  it.asset_id,
  SUM(CASE WHEN it.type = 'buy' THEN it.quantity ELSE -it.quantity END)            AS quantity,
  SUM(CASE WHEN it.type = 'buy' THEN it.amount   ELSE -it.amount   END)
    / NULLIF(SUM(CASE WHEN it.type = 'buy' THEN it.quantity ELSE -it.quantity END), 0) AS avg_cost,
  SUM(CASE WHEN it.type = 'buy' THEN it.amount   ELSE -it.amount   END)            AS total_invested,
  NULL                                                                               AS current_price,
  NULL                                                                               AS current_value,
  NOW()                                                                              AS updated_at
FROM investment_transaction it
LEFT JOIN holding h ON h.asset_id = it.asset_id
WHERE it.status = 'confirmed'
  AND h.asset_id IS NULL
GROUP BY it.asset_id
ON CONFLICT (asset_id) DO NOTHING;
```

This fix is applied in migration `005_fix_price_coverage.sql`.

### Issue 2 — SGBs (SGBMAR28X.NS, SGBMAY29I.NS): Not in Indian Stock Market API

**Root cause:** Sovereign Gold Bonds have `.NS` tickers on NSE but trade with near-zero
liquidity. The Indian Stock Market API does not index them.

**Decision:** Change `price_source` to `gold_api` and `ticker_symbol` to `XAU` for both SGB
assets. Rationale: 1 SGB unit = 1 gram of 24k gold; `GoldAPI` returns `price_gram_24k` in INR.
This gives an accurate gold-equivalent valuation automatically updated on each refresh.

**Fix SQL** (applied in migration `005`):
```sql
UPDATE asset
SET price_source = 'gold_api', ticker_symbol = 'XAU'
WHERE ticker_symbol IN ('SGBMAR28X.NS', 'SGBMAY29I.NS');
```

**Accepted limitation:** SGB market price can trade at a small premium/discount to spot gold
(typically ±2–3%) due to liquidity and time-to-maturity. For a personal tracker, gold spot
price is an acceptable proxy.

### Issue 3 — 7 Illiquid Stocks: BSE-listed but tagged with `.NS` (NSE) tickers

**Root cause:** The following 7 stocks are listed on BSE, not NSE. Their `ticker_symbol`
in the `asset` table has the `.NS` suffix, which causes the Indian Stock Market API to query
NSE data where these stocks do not exist.

| asset_id | name | Wrong ticker | Correct ticker |
|----------|------|-------------|----------------|
| 3  | Archit Organosys Ltd   | ARCHITORG.NS | ARCHITORG.BO |
| 7  | DHP India Ltd          | DHPIND.NS    | DHPIND.BO    |
| 6  | Deepak Spinners Ltd    | DEEPAKSP.NS  | DEEPAKSP.BO  |
| 19 | Prima Plastics Ltd     | PRIMAPLA.NS  | PRIMAPLA.BO  |
| 28 | T & I Global Ltd       | TIGLOB.NS    | TIGLOB.BO    |
| 27 | Teesta Agro Industries | TEEAI.NS     | TEEAI.BO     |
| 29 | Vijay Solvex Ltd       | VIJSOLX.NS   | VIJSOLX.BO   |

The routing code in `AssetPriceService` already handles `.BO` tickers — they are routed to
the Indian Stock Market API exactly like `.NS` tickers (suffix is stripped, bare symbol sent
to the API). The fix is a data change only, no code change needed.

**Fix SQL** (applied in migration `005`):
```sql
UPDATE asset
SET ticker_symbol = REPLACE(ticker_symbol, '.NS', '.BO')
WHERE ticker_symbol IN (
  'ARCHITORG.NS', 'DHPIND.NS', 'DEEPAKSP.NS',
  'PRIMAPLA.NS', 'TIGLOB.NS', 'TEEAI.NS', 'VIJSOLX.NS'
);
```

**Note:** If the Indian Stock Market API does not index these BSE stocks after the ticker fix,
the fallback is to change their `price_source` to `manual` and enter prices manually.
This should be verified after the migration is applied.

---

## Migration

All three fixes are bundled in `backend/migrations/005_fix_price_coverage.sql`. This migration:
1. Inserts missing holding records for any asset with confirmed transactions but no holding row
2. Updates SGB assets to use `gold_api` / `XAU`
3. Corrects `.NS` → `.BO` for the 7 BSE-listed stocks

## Consequences

**Good:**
- All non-manual assets should have non-null `current_price` after next refresh (assuming
  BSE API coverage is confirmed for the 7 illiquid stocks)
- Holdings table is always consistent with investment_transaction ledger
- Integrity check query can be run at any time to detect future regressions

**Bad / Accepted:**
- SGB valuation uses gold spot price as proxy (±2–3% vs actual SGB market price)
- If Indian Stock Market API doesn't cover the 7 BSE stocks, they'll need manual pricing
