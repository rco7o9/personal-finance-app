# ADR-014 — Indian Stock Market API for NSE/BSE Equity Pricing

## Status
Accepted

## Date
2026-04-25

## Context

Phase 2a required live price fetching for ~30 NSE-listed equities (`.NS` tickers). The original implementation (ADR-008) routed all `yahoo_finance` price_source assets to Finnhub. This worked for US equities on Finnhub's free tier, but Finnhub HTTP 403'd all Indian exchange requests — the free plan does not include NSE/BSE data.

We attempted to use the `yahoo-finance2` npm package as a replacement. This package is ESM-only. The NestJS backend compiles as CommonJS (`module: nodenext` without `"type": "module"` in package.json), which means `require()` cannot load ESM-only modules. Dynamic `import()` works at the CJS/ESM boundary, but Yahoo Finance now requires a "crumb" (CSRF token from a cookie-based session) for all quote API calls. Under concurrent load (41 parallel `quote()` calls during a holdings refresh), all requests raced to fetch the crumb simultaneously, causing Yahoo Finance to return HTTP 429 Too Many Requests on the crumb endpoint. Throttling and backoff strategies were considered but Yahoo Finance's aggressive rate limiting on the crumb endpoint makes it unreliable for server-side use.

## Decision

Use the **Indian Stock Market API** (`http://65.0.104.9`) — an open-source, self-hosted API — for all NSE/BSE equity price fetching. US equities continue to use Finnhub (which works on the free tier for US stocks).

Routing logic inside `AssetPriceService.fetchYahooFinance()`:
- Ticker ending in `.NS` or `.BO` → Indian Stock Market API single endpoint
- All other tickers → Finnhub

For the `refreshHoldingPrices` batch operation, Indian stocks are fetched via the `/stock/list` batch endpoint (max 10 symbols per request), processed in sequential chunks of 10 with 1-second retry on HTTP 503/504.

## Alternatives Considered

1. **Yahoo Finance (`yahoo-finance2` package)** — Rejected. ESM-only package causes CJS incompatibility requiring dynamic `import()`. Yahoo Finance's crumb-based authentication causes 429 rate limits under concurrent server-side load. Unreliable for a personal server.

2. **Stooq** — Not evaluated. Would have required CSV parsing and is delayed data only.

3. **Alpha Vantage** — Rejected. Free tier is 25 API calls/day, insufficient for 30+ equities.

4. **Twelve Data** — Not evaluated; would require a new API key.

5. **NSEIndia direct** — Rejected. Requires browser-like session management (cookies + User-Agent spoofing).

## Consequences

**Good:**
- No API key required for Indian stocks — zero operational cost
- Batch endpoint reduces HTTP calls (10 stocks per request vs 30 individual requests)
- Handles transient 503/504 with retry logic
- 47 of 56 non-manual holdings updated successfully

**Bad/Accepted:**
- 9 illiquid small-caps and SGBs (Sovereign Gold Bonds) return no data from this API — these remain with null `current_price` until a data source for illiquid instruments is added
- The API is community-hosted (`65.0.104.9`), not an official exchange feed — availability is not guaranteed; if it goes down, a fallback or alternative source will be needed
- US equities still depend on Finnhub free tier; if Finnhub changes its free tier policy, US stocks will need re-routing
