# ADR-019 — UI Design Philosophy: Dark Theme, Typography, and Dashboard Layout

## Status
Accepted

## Date
2026-04-28

## Context

The application launched with the default shadcn/ui light theme and Geist Sans — the
scaffolding defaults. As the portfolio view matured (Phase 2 complete: XIRR, allocation
bars, per-platform breakdown, rebalancing suggestions), the visual presentation became a
practical concern: the light theme felt generic and the layout was a single-column vertical
stack with no visual hierarchy between sections.

Three decisions were made together as a visual foundation for all future screens:

1. **Permanent dark theme** — the app is a personal finance dashboard used by two people
   in a controlled environment. There is no public-facing or accessibility requirement that
   demands light mode. A single, well-tuned dark palette is simpler to maintain than a
   dual-theme system.

2. **DM Sans as the primary typeface** — the default Geist Sans is clean but neutral.
   DM Sans is warmer and more editorial at display sizes, making large financial figures
   (₹1.25 Cr, 14.2% XIRR) feel intentional rather than incidental.

3. **Two-column dashboard layout for the portfolio overview** — the flat vertical stack
   buried the XIRR figure, mixed navigation (Refresh Prices) into the data area, and
   separated logically related panels (allocation and platform breakdown) with unrelated
   sections in between.

## Decision

### 1. Permanent dark theme — no toggle

`<html>` carries `class="dark"` at all times, set statically in the root layout. The
shadcn/ui CSS variable system is re-pointed: `:root` holds the dark palette directly
and the `.dark {}` override block is deleted.

This means there is no light mode fallback. The tradeoff (no OS-level preference
respected) is acceptable for a private household app.

**Palette anchors (from the reference screenshot):**

| Role | Token | Value |
|---|---|---|
| Page background | `--background` | `oklch(0.09 0 0)` ≈ `#111` |
| Card surface | `--card` | `oklch(0.14 0 0)` ≈ `#1c1c1c` |
| Card border | `--border` | `oklch(1 0 0 / 8%)` |
| Body text | `--foreground` | `oklch(0.96 0 0)` ≈ `#f5f5f5` |
| Secondary text | `--muted-foreground` | `oklch(0.62 0 0)` ≈ `#9ca3af` |
| Sidebar surface | `--sidebar` | `oklch(0.12 0 0)` |

### 2. Semantic accent tokens

Three custom properties express financial meaning independent of Tailwind's palette:

| Token | Value | Usage |
|---|---|---|
| `--color-positive` | `#4ade80` | XIRR, gains, positive returns |
| `--color-overweight` | `#f59e0b` | Overweight allocation badge, over-target bar |
| `--color-underweight` | `#3b82f6` | Underweight allocation badge, under-target bar |

These are referenced as `text-[var(--color-positive)]` in components. Hardcoding hex
values in component classNames is not permitted — always use these tokens.

### 3. DM Sans — four weights, no light mode fallback

Loaded via `next/font/google` with weights 400, 500, 600, 700. Assigned to `--font-sans`.
Geist Mono is retained for `--font-mono`. Geist Sans is removed entirely.

### 4. Portfolio page layout — three-row dashboard grid

The portfolio overview follows a fixed three-row structure:

**Row 1 — Hero metrics (`grid-cols-2`):**
Two equal bordered cards side by side. Left: total portfolio value with date subtitle.
Right: overall XIRR in green with the Refresh Prices action and a platform subtitle.
This separates the two most important figures and gives each visual prominence.

**Row 2 — Detail panels (`grid-cols-5`, 2/5 + 3/5 split):**
Allocation bars (left, narrower) and by-platform breakdown (right, wider) sit side by
side. These panels are contextually related — both show how value is distributed — and
benefit from visual proximity. The 2/5 + 3/5 split gives the platform grid (two columns
of cards) enough room without cramping the allocation bars.

**Row 3 — Rebalancing suggestions (full width):**
Conditionally rendered. Shown below the detail panels rather than between them so it
does not interrupt the scan path from metrics → distribution → action.

### 5. Section headers use muted uppercase tracking

All section labels use `text-xs uppercase tracking-wide text-muted-foreground`. This
creates a clear typographic tier below body text without introducing additional heading
levels. Data is always larger and more prominent than its label.

## Alternatives Considered

### Light/dark toggle
Rejected. Adds state management, `suppressHydrationWarning`, potential flash-of-wrong-theme,
and doubles the CSS variable surface to maintain. The audience is two people who prefer dark.

### System preference via `prefers-color-scheme`
Rejected for the same reason — the preference is known and fixed; responding to OS
settings adds complexity for zero user benefit.

### Tailwind hardcoded colors (e.g. `bg-gray-900`) instead of CSS variables
Rejected. shadcn/ui components use CSS variable tokens internally. Mixing hardcoded
Tailwind color classes with token-based components produces inconsistent surfaces when
shadcn variants are applied. All colors must flow through the token system.

### Single-column layout with reordered sections
Considered as a low-effort improvement (just reorder to: total value, XIRR, allocation,
platform, rebalancing). Rejected because it still buries the two hero metrics in the same
visual tier as the detail panels, and wastes horizontal space on a desktop viewport.

## Consequences

**Good:**
- Single palette to maintain; no light/dark divergence in component classNames
- Semantic tokens (`--color-positive`, etc.) mean financial meaning is expressed once in
  CSS and flows through to any component that renders a positive return value
- Dashboard layout matches the mental model: global metrics at top → distribution in
  middle → actions at bottom
- DM Sans at 4xl/bold makes ₹ figures and percentages feel like data, not UI chrome

**Accepted constraints:**
- No light mode — breaking change if the app is ever shared with users who require it
- `formatDate(new Date())` used for the "As of" subtitle; this reflects the date the page
  was rendered, not the timestamp of the last price refresh (which is not stored in
  `PortfolioSummary`). Acceptable for a private app where refresh is manual.
- Per-platform XIRR shown in the reference screenshot is not rendered — `PlatformSummary`
  does not carry an XIRR field. This is a future backend enhancement if desired.

## Rules Established by This ADR

These apply to all frontend work going forward:

1. **Always** use `--color-positive`, `--color-overweight`, `--color-underweight` tokens
   for financial sentiment colors — never hardcode `#4ade80`, `text-green-400`, etc. directly
2. **Never** introduce light-mode-specific classes (`dark:` variants are dead code)
3. **Always** use `text-xs uppercase tracking-wide text-muted-foreground` for section labels
4. **Ask before** adding any new semantic color token (proposed token + usage + reason)
5. **Ask before** changing the three-row portfolio layout structure
