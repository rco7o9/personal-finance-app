# ADR-012: Portfolio Inception Date Seeding Strategy

## Status
Accepted

## Date
2026-04-24

## Context
The `investment_transaction` table is the source of truth for XIRR and portfolio value.
It requires dated cash flows per asset. However, full transaction history across all
brokers (Zerodha, INDMoney, PayTM Money, CoinSwitch, MF Central) spans 500–600
transactions and is not available in a single consolidated, date-accurate format.

Available data per asset: current quantity held, weighted average buy price (from broker
exports), current market price. Transaction-level dates are not reliably available without
parsing multiple years of individual broker statements.

## Decision
Seed the portfolio using an "inception date" approach: insert **one synthetic BUY
transaction per asset** dated **April 1, 2026 (FY2027 start)** using the known average
buy price and current quantity.

```
is_seed = TRUE
source  = 'seeded'
transacted_at = 2026-04-01
type    = 'buy'
quantity = <current quantity held>
price    = <weighted avg buy price from broker export>
amount   = quantity × price
```

### What XIRR means post-seed
```
Cash flows XIRR sees:
  −(avg_price × qty)     on 2026-04-01   ← seeded BUY
  +(current_price × qty) on today        ← terminal value

= Holding-period return since FY27 start. Honest and clearly labelled.
```

### Why April 1, 2026
- Aligns with Indian financial year start — natural benchmark for Indian investors
- XIRR from this date forward will be accurate as all future transactions are real
- Pre-seed performance is acknowledged as not tracked, not silently wrong

### Idempotency guard
The seed script checks `SELECT COUNT(*) FROM investment_transaction WHERE is_seed = TRUE`
before running. If any seeded rows exist, it exits without inserting duplicates.

### Input format
A CSV file (`scripts/portfolio.csv`) with columns:
`symbol, name, category, subcategory, financial_institution, quantity, avg_price, currency`

The seed script runs: asset upsert → investment_transaction insert → holding upsert.

## Alternatives Considered

### Import full historical transaction history
Rejected for now. Would require parsing 500–600 transactions across multiple broker
formats with accurate dates. The effort is only worthwhile if a CDSL CAS statement or
Zerodha capital gains report is available with exact transaction dates. Can be done
retroactively in a later phase without any schema changes — the `investment_transaction`
table already supports it via `source = 'imported'`.

### holdings_snapshot table as seeding artifact
Considered and dropped. The seeded BUY transaction already records qty, avg_cost, total
invested, and seed date. A separate snapshot table would duplicate this data with no
additional value.

## Consequences
- All XIRR figures shown in the app carry an implicit "since FY2027" qualifier
- The `is_seed` flag allows the UI to display this qualifier next to XIRR values
- Future imported historical transactions (source = 'imported') can be inserted alongside
  seeded rows — the holding recompute logic handles mixed sources correctly
- The seed script is a one-time manual operation run before Phase 2a end-to-end testing
